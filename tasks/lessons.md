# Lessons

## 2026-07-24 — 先核对运行时 Prompt 再判断翻译错误

### Trigger

- 用户报告某个具体输入未按目标语言翻译。
- Provider 使用可编辑 Prompt，且输入可能被识别为代码、名称或技术标识符。

### Rule

- 先核对精确源文本、实际检测语言、实际目标语言和运行时生效的完整 Prompt。
- 逐条确认输入命中了哪项翻译、保留或格式规则，再判断是 Prompt、模型还是请求组装问题。
- 不根据模糊截图推断源文本或命中的 Prompt 分支。

### Check

- 根因结论引用精确输入和运行时 Prompt 中直接导致结果的具体规则。
- 已排除目标语言解析和请求组装问题后，才把问题归因于模型行为。

- 用户明确不需要 Sparkle 自动更新发布时，应把 GitHub Release 工件与 appcast 更新链路分开：保留普通 ZIP/DMG 发布，只移除 Sparkle 密钥、appcast 生成与上传要求。
- 设计“多语义翻译”提示词时，必须把短歧义文本的多义枚举写成高于默认单译的强制分支，并明确可能性只决定排序、不能过滤常见且结构不同的解释；随后再按解释聚类并只保留每组最准确自然的一个裸译文。
- 修复 AppKit 首次聚焦问题时，应以目标视图的 `viewDidMoveToWindow()` 等真实挂载生命周期为同步点，并用真实窗口层级断言 first responder；不要只靠异步派发或窗口通知推测时序。
- 新增支持多模型的 Provider 时，必须同时验证模型目录、可见选择界面和执行层的模型选择；不能只提供一个可编辑的默认模型字段。
- 为 UI 增加键盘快捷键时，必须同时检查对应界面是否有可见提示；如果用户提到 badge、hint、shortcut label，不能只实现键盘事件。
